1. 节点全景图

H3 相关共 6 个节点，另加 LLM 推理 3 个、文本工具 3 个。核心逻辑：素材只进一次「参考素材」，同一份素材包分给提示词框（@引用）、LLM 生成（多模态）、解包（接到官方/T8 Ref2VA）。模型主干：LoRA 选择器 → 模型加载器 → H3 参数包装 → LLM 通用生成。

3. 节点参数详解

以下值域均来自节点代码 INPUT_TYPES，与实际下拉/滑条一致。

① LLM LoRA 选择器 —— 选适配器、调强度

LLMLoraSelector
参数默认范围/选项控制什么 · 效果
LoRA模型None（不启用）models/LLM 下自动识别出的 GGUF 适配器选中后给基座挂上适配器（如 MiniMax-H3-Prompt-Rewriter-LoRA-F16.gguf）；选 None 则不挂。按 GGUF 元信息自动与基座模型区分，不会混入下拉。
权重scale1.00.0 ~ 2.0，步长 0.05LoRA 生效强度：越大改写/风格倾向越强，过大易崩；为 0 等于不挂。
输出：LoRA配置（未选模型时为 None，加载器不挂 LoRA）

② LLM 模型加载器 —— 决定用什么模型跑

LLMModelLoader
参数默认范围/选项控制什么 · 效果
基座GGUF列表首个models/LLM 下非 mmproj、非 LoRA 的 .gguf要加载的基座大模型。
mmproj文件NoneNone 或 mmproj*.gguf多模态投影层：纯文本模型必须 None；要看图/视频的模型必须选配套 mmproj，否则视觉输入报错。
对话处理器NoneNone / LLaVA / MiniCPM / Gemma / Qwen2.5-VL / Qwen3.8 / Qwen3-VL / Qwen3.6 / Qwen3.5 / GLM …chat 模板与多模态解析，必须与基座架构一致。Qwen3.8/3.6/3.5 的 GGUF 架构都是 qwen35，选错处理器会模板不对。纯文本 T2VA 可留 None，或选 Qwen3.8 且 mmproj=None。
GPU层数-1-1 ~ 200-1=全部层进 GPU（最快）；0=纯 CPU；显存不够时往下调。
上下文长度8192512 ~ 131072模型“看得见”的 token 上限；素材多/提示词长就要加大（生成节点会估算并拦截超限）。
显存限制GB-1-1 ~ 999仅当 GPU层数=-1 时生效：-1=尝试全部进 GPU；填数值=按预算自动计算 GPU 层数。Qwen3.8 很大，显存不够请先填 8 再往上加。
思考模式关开 / 关关=直接给答案；开=先推理再答（输出含 <think>，生成节点会自动剥掉）。官方 LoRA 必须关。Qwen3.8 还须同时把推理强度设为非关闭。
Qwen3.8推理强度关闭关闭 / 自动 / 低 / 中等 / 高仅 Qwen3.8 生效。关闭=不思考；自动/高=最高档（xhigh）；低/中等=降低思考强度。改此参数会重新加载模型。
图像最小/最大token256 / 102464 ~ 4096每张图压缩成多少 token：越大看图越精细，越吃上下文和显存。
LoRA配置（可选输入）不接接「LoRA 选择器」挂载 LoRA 适配器；换 LoRA 或改 scale 时缓存自动刷新。
输出：模型句柄（进程内加载并缓存，同一句柄可被多个生成节点复用）

③ H3 参考素材 —— Autogrow 打包首尾帧 / Ref2VA 素材

H3ReferenceMedia · V3
槽位命名与官方 Ref2VA / T8 一致：首尾帧固定为 first_frame / last_frame；参考类使用 Autogrow 渐进槽位（接满 ref_image_0 后出现 ref_image_1 …，最多 9 路）。<Picture N> 为紧凑顺序号，与 T8 相同。
参数默认范围/选项控制什么 · 效果
图像最大边长1024256 ~ 2048输入图统一缩放边长：越小越省 token。
视频最大帧数41 ~ 16参考视频抽帧数（本地视觉模型基本不吃视频流，用抽帧近似）。
首帧图 / 尾帧图不接IMAGE对应官方 Image to Video 的 first_frame / last_frame。
ref_image_0 … ref_image_8AutogrowIMAGE，0~9 路与官方 Ref2VA 的 ref_image_0… 一一对应（从 0 起编号）。
ref_video_0 … ref_video_2AutogrowVIDEO，0~3 路对应官方 ref_video；llama 侧抽帧分析，解包仍是原始 VIDEO。
ref_video_audio_0 … 2AutogrowAUDIO，0~3 路对应官方 ref_video_audio。
ref_audio_0 … ref_audio_2AutogrowAUDIO，0~3 路对应官方 ref_audio。
输出：素材包。自动识别：有参考图/参考视频 → Ref2VA；否则 首+尾帧 → FL2VA；仅首帧 → I2VA；仅尾帧 → L2VA；啥都没有 → T2VA。接了 Ref 素材时，@ 菜单不把首尾帧编进 Picture 号。

⑤ H3 提示词框（可@）—— 写想法并引用素材

H3PromptBox

把「参考素材」的素材包接到本节点。在文本框输入 @ 弹出已接线的图/视频/音频，插入官方标签（<Picture N> 等为紧凑顺序号）。输出的提示词接到「H3 参数包装」的「原始视频需求」（右键转输入）；素材包可透传给 Builder / Generator / 解包。

输出：H3提示词 / 素材包（透传）

④ H3 参数包装 —— 组装系统提示词与用户消息

H3PromptBuilder

不做推理。按 H3 模式、时长、比例、提示词版本，把「原始视频需求」和可选素材包组装成 系统提示词 + 用户消息，连到「LLM 通用生成」。

参数默认范围/选项控制什么 · 效果
原始视频需求占位文本多行文本（可转输入）你的视频想法。可接「提示词框」的 H3提示词输出。
提示词版本精简（小模型推荐）精简 / 完整（云端契约）/ 官方LoRA模板(T2VA)系统提示词来源；挂 H3 Rewriter LoRA 时选第三个。
H3模式自动识别自动识别 / T2VA / I2VA / FL2VA / L2VA / Ref2VA写哪种任务的提示词；自动识别=按素材包判定；官方LoRA模板下锁定 T2VA。
目标时长51 ~ 120 秒视频目标长度。
视频比例16:916:9 / 9:16 / 1:1 / 4:3 / 3:4画幅。
额外系统提示词（可选）不接STRING可接「系统提示词选择器」或手写，追加到自动组装的系统提示词。
参考素材（可选）不接来自「参考素材」用于模式识别与用户消息中的参考描述；透传素材包给下游。
输出：素材包（透传）/ 系统提示词 / 用户消息 / 识别模式

④b LLM 通用生成 —— 本地推理产出文本

LLMGenerator
参数默认范围/选项控制什么 · 效果
模型句柄必接来自「模型加载器」用哪个模型做改写。
系统提示词空多行文本接「H3 参数包装」的 系统提示词，或任意自定义系统提示。
用户消息空多行文本接 Builder 的 用户消息，或任意用户输入。
温度0.70 ~ 2随机性/创造性（越低越稳定）。
top_p0.90 ~ 1采样核裁剪。
top_k400 ~ 100每步候选词数。
重复惩罚1.10 ~ 2抑制重复输出。
最大输出token204864 ~ 8192输出长度上限。
seed00 ~ 2³¹随机种子；ComfyUI 右键菜单可控制是否每次随机。
⚡推理后卸载模型关布尔生成完立即释放显存。
多模态素材（可选）不接来自「参考素材」图/视频抽帧/音频送入 mmproj 模型；官方LoRA 模板用户消息下会被忽略。
输出：生成文本（剥掉 think 的干净版，即 H3 提示词）/ 原始响应（模型原文，含 think）

⑥ H3 素材解包 —— 拆回官方 / T8 对应口

H3MediaUnpack · V3

输入素材包，按打包时的槽位原样输出首帧/尾帧/参考图/参考视频/视频音轨/参考音频。接到官方 MiniMax H3 或 T8 Ref2VA 节点，和当初直接接图效果相同。

输出口显示规则：first_frame、last_frame 始终显示；ref_image_*、ref_video_*、ref_video_audio_*、ref_audio_* 按上游打包实际接入动态显示（前端 JS 裁剪，与 Autogrow 行为一致）。未接入的 ref 口不会占位显示。

⑦ 系统提示词选择器 —— 从 prompts/ 选 txt

PromptSelector

递归扫描插件内 prompts/**/*.txt，下拉选择后输出文件全文。可接到「H3 参数包装」的 额外系统提示词，或任意需要系统提示词的节点。

输出：system_prompt

⑧ 多路文本选择器 —— 多路文本各选一行

TextSelector

最多 10 路 text_N 输入（前端渐进显示），每路从多行文本中选一行或随机，另有 merged 合并输出。适合台词库、风格变体等场景。

输出：merged / out_1 … out_10

4. 任务接线速查

用官方 LoRA 优化文本改写

LoRA选择器 → 模型加载器 → 参数包装 → LLM 生成
  • LoRA 选 …Rewriter-F16.gguf，scale 1.0
  • 加载器：Qwen3.6-27B + mmproj=None + 处理器 Qwen3.6 + 思考模式=关
  • Builder：提示词版本=官方LoRA模板(T2VA)，不接素材
  • Generator：接 Builder 的 系统提示词 + 用户消息，不接多模态素材

图生视频（I2VA / FL2VA / Ref2VA）

参考素材 → 提示词框 → 参数包装 → LLM 生成；参考素材 → 解包 → 官方/T8 H3
  • 加载器用视觉 GGUF + mmproj（如 Qwen3.8 / Qwen3-VL 系）
  • 在提示词框用 @ 引用素材；Builder「原始视频需求」转输入接框输出
  • 参考素材同时接 Generator「多模态素材」，模型才能看见图
  • 解包 ref_image_0 等与官方 Ref2VA 一一对接

纯文本改写、无 LoRA

模型加载器 → 参数包装 → LLM 生成
  • 任意 instruct GGUF，mmproj=None
  • Builder 用精简版；可选 PromptSelector 追加额外系统提示词

音频驱动 / 加参考音频

参考素材（接 ref_audio_0）→ 参数包装 + LLM 生成
  • 处理器需支持 input_audio（如 Qwen3-VL 系）
  • 纯音频时模式自动落 T2VA

最小用法（标准主干）

  1. 把 GGUF 基座 / mmproj / LoRA 适配器放进 ComfyUI/models/LLM/（目录名大小写不敏感）
  2. 「LoRA 选择器」选适配器（不需要就留 None）→ 连「模型加载器」
  3. 「模型加载器」选基座 + mmproj + 对话处理器 → 输出「模型句柄」连「LLM 通用生成」
  4. 有图/视频/音频参考就接「参考素材」→ 素材包连「H3 参数包装」；图生时同时连 Generator「多模态素材」
  5. 「H3 参数包装」填「原始视频需求」，选版本/模式 → 系统提示词 + 用户消息连「LLM 通用生成」→ 得到 H3 提示词
  6. 需要接官方生视频节点时：参考素材 →「素材解包」→ 官方/T8 Ref2VA

5. 常见问题与坑

官方LoRA模板模式下别接多模态素材——LLMGenerator 检测到 LoRA 模板用户消息时会忽略素材包（该 LoRA 仅 T2VA 文本改写）。
图生必须接 Generator「多模态素材」——仅把素材包连到 Builder 不够，模型要通过 Generator 的多模态口才能看见参考图。
打包/解包节点消失或槽位仍是「参考图1」——需 ComfyUI V3 API；完全重启 ComfyUI 并 Ctrl+F5 硬刷新；删除旧版 h3_media_slots_ui.js（若仍存在）。
官方 LoRA 要求思考模式=关——开启时模型会先输出大段推理再写结果。Qwen3.8 请同时把「Qwen3.8推理强度」设为关闭。
Qwen3.8 要 llama-cpp-python 0.3.47+——旧版会报 missing tensor 'blk.64.ssm_conv1d.weight'。请从 JamePeng Releases 装匹配的 GPU wheel。思考必须「思考模式=开」且「推理强度≠关闭」。
报「上下文预算不足」——优先加大加载器的「上下文长度」；其次调低「图像最大token」（当前用于估算每张图），或减少素材数量/参考视频帧数。若推理时才溢出，同样是这几招。
换 LoRA 或改 scale 不生效？——modern API 下 scale 已移出缓存 key、缓存命中时自动刷新；若用 legacy API 且 llama-cpp-python 不支持 lora_scale，权重会被忽略（有警告）。
复现结果——Generator 的 seed 固定 + ComfyUI 右键关闭随机化，每次生成前会显式复位 RNG。
参考视频精度——本地视觉模型基本不读视频流，参考视频走「抽帧为图像」近似；要稳就用图片/首末帧。
覆盖系统提示词——prompts/h3/official/h3_system.txt（完整）/ h3_system_lite.txt（精简）/ h3_lora_template.txt（官方LoRA固定模板）覆盖后重启 ComfyUI 生效；也可用 PromptSelector 从 prompts/ 子目录选文件。
小模型能力边界——本地小模型对 H3 复杂结构化提示词的理解力弱于云端 Gemini/Seedance，已提供精简版缓解；音频输入仅部分 chat handler 支持。
