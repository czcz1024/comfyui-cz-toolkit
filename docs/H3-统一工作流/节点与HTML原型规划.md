# H3 统一工作流 — 节点与 HTML 原型规划

> 配套：`开发说明.md`（需求总纲）  
> 开发策略：**先 HTML 模拟操作与数据契约 → 你试用确认 → 再落成真正 ComfyUI 节点**  
> **自测**：见《开发说明》**§16**（样式/Lab 开发侧先截图验；真采样与重启需本机配合）  
> 状态：规划中 / 需求已收口 / 未实现  
> 日期：2026-09

---

## 1. 为什么先做 HTML

| 原因 | 说明 |
|------|------|
| 交互重 | 多段切点、每段素材/文案、镜间续或新，适合先在浏览器里把「好不好用」试清楚 |
| 契约先稳 | HTML 与日后节点共用同一套 **Plan JSON / Prompt Pack**，避免节点写完再推翻 UI |
| 风险低 | 不先绑 Comfy 执行图、不先碰采样循环；确认后再嵌进节点 DOM 或侧栏 |
| 有先例 | 本仓库已有 `h3-prompt-formatter-lab` + 排版台嵌入路径，可复用这套「Lab → 节点」节奏 |

### 1.1 推荐目录（实现时）

```text
ComfyUI-CZ-Toolkit/
  docs/H3-统一工作流/          ← 需求与本规划
  h3-unified-lab/              ← 新建：纯静态/本地 HTML 原型（模拟操作）
    index.html                 ← 入口：单段 / 多段导演台切换
    …                          ← 与日后 web/ 共用的 schema、样式可再抽
```

Lab **不调用**真实 H3 采样；可用假数据、本地 JSON 导入导出、可选接已有 LLM HTTP（若你已有）——第一版甚至可全 mock。

**当前已有：** `h3-unified-lab/index.html` — Comfy 风格节点外观 / 接线模拟（双击或浏览器打开即可预览）。

### 1.2 Lab 分屏（建议你先试用的页面）

| 页 | 对应日后能力 | 试用要确认什么 |
|----|--------------|----------------|
| **A. 单段控制台** | 生成模式下拉、LLM 开/关、二采开/关、想法→prompt、素材槽位列表（模拟 Load 结果） | 单段心智是否够用 |
| **B. 多段导演台** | 波形/切点、段列表、每段素材引用、文案、镜间关系、选段 | 人机共驾是否顺手 |
| **C. 计划 JSON 预览** | 导出/导入 `H3_SEGMENT_PLAN` | 字段是否够、改起来是否直观 |

确认顺序建议：**先 A → 再 B → 契约锁定后再写节点**。

## 3. 各节点说明书（目标接口）

以下类型名以规划为准；落地时可映射为 `H3_SEGMENT_PLAN`、`H3_MODEL_BUNDLE` 等。

---

### N0 — H3 项目素材库（`H3MediaLibrary`）

**干什么：** 多段项目的大素材池。用户设 `image_count` / `video_count` / `audio_count`，左侧口随之增减；接官方 Load*，打成 `H3_MEDIA_LIBRARY` 给导演台。

| 项 | 说明 |
|----|------|
| **控件** | `image_count` / `video_count` / `audio_count`（INT） |
| **输入（随 count）** | `image_*`（IMAGE 静图）；每个 video → `video_*`（**IMAGE 帧**）+ `video_audio_*`（**AUDIO 伴音**，可空）；`audio_*`（独立 AUDIO） |
| **输出** | `library`（`H3_MEDIA_LIBRARY`）含稳定 id + 媒体 |
| **库上限（首版建议）** | 27 静图 / 9 视频对 / 9 独立音 |
| **编辑器** | 轻量：改 count 时增删口（学 Easy MediaBridge UX；口类型跟本仓 ReferenceMedia） |
| **不做** | 节点内上传；整段 `VIDEO` 单口；单口虚拟多线 |

**例子：** 2 视频 + 2 独立音频 → 口为  
`video_1`(IMAGE)、`video_audio_1`(AUDIO)、`video_2`(IMAGE)、`video_audio_2`(AUDIO)、`audio_1`、`audio_2`。

与已有 `H3ReferenceMedia`：**单段 9/3/3 仍用后者**（同样是画面 IMAGE + 视频伴音 + 独立音）；多段导演台吃 N0。

### N3 — H3 多段计划台 / 导演台（`H3SegmentDirector`）★ 核心

**干什么：** 人机共驾的中枢。持有并编辑整份 **多段计划**；自动切分后改切点、每段素材、文案、镜间关系；**不负责采样**（采样在 **N8 段执行台**）。

| | |
|--|--|
| **输入** | **`library`**：台上枚举音频选一条再自动切分；**`llm_handle`（可选，`H3_MODEL_HANDLE`）**：接 `LLMModelLoader`，润色用；**不另接 AUDIO，不接 draft_plan** |
| **输出** | `plan`（`H3_SEGMENT_PLAN`）；`boundaries_json`；`active_segment_index` |
| **参数（节点级）** | `project_name`；隐藏 `plan_json`（**无**模型/mmproj/URL 控件） |
| **编辑器** | **是 — 导演台级自定义 UI**（见 §5） |
| **HTML Lab** | **主原型**；先定交互再嵌 Comfy |

**计划内每段建议字段：**

```text
segment_id, start_s, end_s,
model_family,            # auto | base | ref
mode,                    # T2VA|I2VA|FL2VA|L2VA|Ref2VA
ref_intents[],
continuity,              # continue | new
media_refs[],            # 库 id；采样前 remap ≤9/3/3
# 二采 refine 不在 plan：默认全关，仅在 N8 按段开
# 执行台另存：backbone / sampler / refine / upscale_scale 等
prompt_zh, prompt_draft, prompt_final,
notes, seed, …
```

**自动切分：** 选库内一路音频 → 切点标注 → 试听/微调（人机共驾）。  
**本地 LLM：** 复用 **`LLMModelLoader` 句柄口**；前端认线读 widget（同 `@`），CZ 自启 llama-server；**不**在导演台扫盘选模、**不**只填 URL。见《开发说明》§6.7。  
**不做：** 节点内上传；独立草案节点；一键无人值守跑完全片。

### N7 — H3 模型收集（`H3ModelCollect`）

**干什么：** **只收集**，不做加速、不采样。用户在上游自己串 LoRA / sage / sol / cache 等，再接到本节点。

| | |
|--|--|
| **输入（6 个 MODEL/CLIP/VAE 口）** | `fl2va_model`；`ref2va_model`；`hybrid_model`；`text_encoder`；`video_vae`；`audio_vae` |
| **控件（放大专用）** | **`latent_upscaler`**：下拉选 `ComfyUI/models/latent_upscale_models/` 里的权重（与 [Comfyui_Minimax_h3_latent_Upscaler](https://github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler) 同一套，如 `minimax_h3_latent_upscaler_3d_fp16.safetensors`）；可空 = 不做二采 |
| **输出** | `models`（`H3_MODEL_BUNDLE`，含上列 + upscaler 文件名） |
| **编辑器** | 否 |
| **说明** | 放大模型**不是**第四个扩散 MODEL，而是 Latent Upscaler 的学习型网络权重；该社区节点用 combo 读盘，没有 MODEL 线可接，故收集节点用**同目录下拉**收进 bundle。混合有时比纯 Ref 好、有时差；各骨干加速 LoRA 仍在上游自串。 |

**二采路径（社区通行；实现按《开发说明》§10.2）：**  
低分一采（本段骨干 MODEL）→ **经适配器调** `Comfyui_Minimax_h3_latent_Upscaler` 公开节点入口（bundle 权重名 + 本段倍数）→ 高分二采（仍用本段骨干 MODEL）。  
不深 import 对方私有逻辑、不默认把对方源码拷进 CZ。段开了 refine 但未选权重 / 对方未安装或接口对不上 → **硬报错**，不静默跳过。

### N8 — H3 段执行台（`H3SegmentRunner`）★ 多段采样核心

**干什么：** 与**计划台同构的第二块台子**。吃进 `plan` 后，用**同一套轨道形态**展示各段（时长/切点/素材占用），但**轨道只读、不能再改计划**。台下（或选中段面板）为**每一段分别**设采样：骨干模型、sampler、sigma、seed、steps 等——**全部在这一节点里设完**，再节点内循环采样。

| | |
|--|--|
| **输入** | `plan`；`models`（N7）；可选 `library` |
| **输出** | `results_manifest`；可选预览 `VIDEO` |
| **与计划台关系** | 计划台定：段多长、走什么流程、提示词；执行台**继承分段**，只加「怎么采」 |
| **UI** | **只读多轨** + 段页签 + **每段**：骨干、sampler、sigma、seed、steps、**refine 开关、放大倍数（手填）**、**Motion-Context 开关（+ 参数）**… |
| **操作** | **生成全部** / **只生成当前段**（Queue 时按用户所选执行）；覆盖 / 另存新版本 |
| **不做** | 改切点/改文案（回计划台）；节点内上传；替用户挂加速 |

每段执行字段（示意，写入 plan 扩展或执行台侧持久化均可）：

```text
backbone,     # fl2va | ref2va | hybrid
sampler_name, # euler / uni_pc / …
scheduler,    # 或 sigma 策略名
steps, cfg, seed,
refine,              # 本段是否二采（默认 false）
upscale_scale,       # 手填浮点，约 1.0–4.0；非下拉
use_motion_context,  # 本段是否接 Motion-Context（默认 false；与 refine 同级用户开关）
motion_overlap_frames, # 开 MC 时可选，如 22
# 其它本段采样相关…
```

### N6 — 选片对比 / 拼接（学 Easy-Media）★ 成片前最后一站

**干什么：** 执行台落下的**各段 × 多版本**结果，在一个台子里**看、比、选**，再按 plan 顺序拼成完整视频。不是「随便接个 VIDEO 口」。

| | |
|--|--|
| **输入** | `results_manifest`（各段各版本路径/元数据）；`plan`（顺序与时长，用于拼接） |
| **输出** | 成片 `VIDEO`；`project_manifest`（每段最终选用哪一版） |
| **编辑器** | **必须有轻量 UI**（可比执行台简单，但要比「一行 note」细得多） |

#### UI 建议模块

1. **按段分组的版本墙**  
   - 段0 / 段1 / 段2… 各一块。  
   - 每块内：该段所有版本卡片（缩略图或首帧、`v1`/`v2`/`v3`、骨干、seed、生成时间）。  
   - **当前选用**高亮（单选）；可点「设为成片用」。

2. **对比**  
   - 同段内勾选 2 个版本 → 并排预览（或左右切）。  
   - 可选：和**上一段选用版**的尾帧并排，看接缝。

3. **单段操作**  
   - 播放该版本；删除废版；备注。  
   - 不在这里改采样参数（回执行台重跑 → 新版本或覆盖）。

4. **成片条**  
   - 按段列出「最终选用：段0→v2，段1→v1…」。  
   - **拼接成片**（按 plan 切点/顺序；可选混原曲——后期再定）。  
   - 导出成片路径 + 更新 manifest。

#### 数据（manifest 示意）

```text
segments[i].versions[] = {
  id, label,       # "v2"
  path, thumb,
  backbone, seed, steps, created_at,
  selected: bool   # 该段成片用哪一版
}
```

**不做：** 改 plan 文案/切点；重新采样（那是执行台）；节点内上传。

## 4. 推荐接线关系（多段主路径）

[LLMModelLoader] ──llm_handle──────────► ★ N3 导演台 → plan

## 5. 自定义编辑器需求

| 节点 | 是否需要 | 规格 |
|------|----------|------|
| N3 导演台 | **必须** | 计划编辑（见下） |
| N8 段执行台 | **必须** | 按段选模型/采样 + 生成控制；轨道只读 |
| N6 选片 | **必须有** | 按段版本墙 + 对比 + 成片选用条 + 拼接（见 §N6） |
| N0 / N7 | **不需要** | 标准控件 |

### 5.1 导演台 UI（N3 / HTML Lab）建议模块

1. **音频选择**：从 bundle 枚举 `ref_audio_*`，下拉选一条用于切分/试听。  
2. **自动切分按钮**：对该音频跑切分 → 时间轴出切点与分段色块。  
3. **多轨时间轴（参考 TimelineDirector）**：  
   - 标尺 + **视频/图轨**：绝对定位 clip（拖整体、左右边裁剪范围、选中高亮、可吸附切点）；不是几个文字块拼成的伪轨道。  
   - **音频轨**：**真波形**（解码音频绘制）+ 粉色切点（可拖）+ **共用红色播放头**（播放前进；可点/拖 seek；可选吸附）。  
4. **试听控件**：播放 / 暂停 / 停止；切点 ◀▶ 微调；增删切点。  
5. **段列表 / 段详情**：  
   - **模式区**：先选底模族（自动 / Base / Ref）；Base 下再定 T2VA…L2VA；Ref 下用**玩法卡片/标签**（普通参考、对口型、换人等，可多选）。  
   - continuity、图/视频轨绑定、**中文意图**（英文由 LLM 写回；**不暴露 H3 六段字段**）；素材用 **`@` 列表**挑选，**不做缩略图墙**。  
6. **工具条**：本段/全部 LLM、导出 plan；状态行可显示「已认到 Loader：基座 / mmproj」（前端认线）。

**明确不做进导演台：** 文件上传；独立草案节点；云端提示词 API；**台内重复选 GGUF/mmproj**；**只填 llama URL**；**真正采样**；**二采 refine**（默认全关，只在 N8 开）。

### 5.2 段执行台 UI（N8）——与计划台同构、只读 + 每段采样

执行台**看起来像计划台**：同一套标尺 / 视频图轨 / 音频切点轨，数据来自 plan。

| 计划台 | 执行台 |
|--------|--------|
| 可拖 clip、可改切点、写提示词 | **轨道只读**（不能改时长/切点/文案） |
| 定 mode / 意图 / 素材绑定 | **定怎么采**：模型、sampler、sigma、seed… |
| 输出 plan | 读 plan，**节点内采样** |

模块：

1. **只读多轨**（视觉对齐导演台；禁止拖裁/改切点）。  
2. **段页签**：点哪段，下面面板切到哪段的执行参数。  
3. **当前段执行面板**（每段一套，存在本节点）：  
   - 骨干：FL2VA / Ref2VA / 混合  
   - sampler、sigma/scheduler、steps、seed（及需要的 cfg 等）  
   - **二采 refine**：开/关；开则 **手填放大倍数**（约 1.0–4.0），用 N7 的 `latent_upscaler`  
   - **Motion-Context**：开/关（默认关）；开则可调重叠帧等（对齐社区常用值）  
4. **生成全部** / **只生成当前段**（Queue 执行用户所选）；**覆盖** / **另存新版本**。  
5. （可同壳）结果列表 → 选片 / N6。

## 5.3 补充：LLM 与组合（与开发说明对齐）

- 导演台出 **plan**；LLM **按段多次**调用；结果写回各段 `prompt_final`（文案组合）。  
- H3 **按段多次**采样后再拼接（视频组合）。  
- 后端：接 **`LLMModelLoader`**；前端不 Queue 认线读配置（同 `@`）→ CZ 自启 llama-server。  
- **调用契约**：`system` = 内置 `prompts/h3/official/`（按本段 mode / Task）；`user` = 任务元数据 + **用户中文**；输出英文写回 `prompt_final`。与 `H3PromptBuilder` 同一套规则，禁止另起冲突文案。
