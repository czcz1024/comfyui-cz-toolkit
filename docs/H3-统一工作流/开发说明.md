---

## 1. 背景与痛点

MiniMax H3 能力面很宽：文生（T2VA）、首帧 / 尾帧 / 首尾帧、多参考 Ref2VA、latent 放大二采、长视频续拍、口型锁音等。社区已有多套编排包（T8 Vocal Lock、Easy-Media、MiniMaxH3-Easy、TimelineDirector、AIMixer Director、Motion-Context 等），各自在某一玩法上做得深，但：

1. **没有一套符合本仓库目标的统一壳**：换玩法往往等于换整张工作流。
2. **多数产品自带上传图控件**：无法从 Comfy 已加载图库里选，每次重传更麻烦。
3. **本仓库已有提示词相关节点**（参数包装、排版台、提示词框、本地 LLM），但入口分裂、主路径不清，不好用。

本需求要解决的是：**同一张（或同一类）工作流骨架，用下拉切换玩法；提示词可手写也可选用 LLM；素材一律走官方加载节点；长视频 / 多镜头在自动草案之上必须可人审人改。**

---

## 2. 目标与非目标

### 2.1 目标

1. 提供较统一的 H3 工作流骨架：用户主要改「模式下拉 + 接线 + 想法 / 提示词」，即可覆盖常见玩法，而不是为每种玩法从零搭图。
2. **可选**利用**本地** LLM：配置统一走已有 **`LLMModelLoader`（句柄）**；单段图用 `LLMGenerator` 进程内加载；导演台接同一句柄口，**前端认线读 widget（同 `@`）**后由 CZ 自启 llama-server 润色，**不必为润色 Queue 整图**。不依赖云 API，不在导演台重复扫盘选模。
3. **可选**启用放大二采（refine）；默认可不启用，由人灵活开关，不绑死进主路径。
4. 尽量使用 **Comfy 官方 H3 条件 / 采样节点**，以及社区包中**可稳定接线的底层能力**。
5. 素材入口坚持 **官方 `Load Image` / `Load Video` / `Load Audio`（或等价原生加载）→ CZ 打包 → 解包到官方口**；禁止节点内自建上传图控件。
6. 把现有 CZ 提示词节点收成**一条可跳段的主链**（LLM 可跳过），排版台作为手改 / 结构预览，与「可选 LLM」共存而非两套对立产品。
7. **长视频 / 多镜头：人机共驾**——自动只出草案（切点、分段提示词、默认镜间关系等），人审核与调整后再生成；支持每段不同素材、改切点、改文案、选「接上镜 / 全新镜头」。

### 2.2 非目标（第一期明确不做）

- 不做 Easy / Director 式巨石「一节点吞掉编辑 + 采样 + 多段 + 选片」。
- 不做节点内重新上传图片 / 视频（无法复用已加载资源）。
- 不强行焊接 T8 Vocal Lock 整链、Easy-Media Project Combine、TimelineDirector 私有清单格式。
- 不替代官方写作指南；规则对齐官方 base / ref，不自创一套冲突契约。
- 不在核心 ComfyUI / 本插件里加联网遥测；LLM 保持本地已有路径。
- **不以「全自动、无人审核的长片一键跑完」为成功标准**（尤其反对 T8 MV 式规划完就串行全跑、中间难插手作为主路径）。

## 3. 设计原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **官方优先** | 生视频主路径：官方 `MiniMaxH3*` 条件 → 采样 → VAE → 保存。 |
| 2 | **能串就串，不硬焊** | T8 lock、Motion-Context 续拍、他人 refine 等作**可选旁路**；稳定算法（如 Latent Upscaler）用**软依赖+适配器**调公开入口；UX/产品壳自写。细则见 §10.2。 |
| 3 | **原生加载素材** | 图/视频/音频只从原生 Load 节点进入；CZ 只做打包 / 解包 / 引用清单。 |
| 4 | **玩法 = 配置，不是新图** | 生成模式 + 编排相关选项用下拉 / 开关切换；尽量一张骨架图。 |
| 5 | **能力可选，人控开关** | **LLM、放大二采等均为可选**：启用或关闭由人决定；关闭后工作流仍完整可跑。 |
| 6 | **人机共驾** | 自动给初稿；切点、每段素材、每段内容、镜间续拍策略等均可二次修改后再生成。 |
| 7 | **有 LLM 则写回 plan** | 选用 LLM 时：台内按段写英文定稿；**多段不做独立归一节点**。不用 LLM 时手写英文即可。 |
| 8 | **改动面小** | 新能力优先落在 `ComfyUI-CZ-Toolkit`；少改、可渐进交付。 |

## 4. 目标形态（用户心智）

**单段：**

```text
接原生 Load → 选生成模式 → 写想法或英文
        →（可选）LLM 出英文 →（可选手改 / 排版台）
        → 官方条件生成
        →（可选）放大二采 → 保存
```

**多段 / 长视频 / MV（人机共驾）：**

```text
自动草案（切点 + 每段 draft 提示词 + 默认镜间关系）
        → 人审：改切点 / 每段素材 / 每段文案 / 接上镜或全新镜头
        → 确认后逐段或选段生成（可只重跑某段）
        →（每段或全局可选）二采
        → 合并 / 选片
```

用户常改的几样：

1. **模式下拉**、**二采开/关**、**LLM 用/不用**
2. **接哪些 Load 节点**（含多段时每段引用）；空口不算
3. **想法 / 提示词**（可自动草稿后再改）
4. **多段时的切点与镜间策略**（自动不准就人改）

**多段时提示词写在哪（已拍板）：** 在**导演台**按段写中文（或改英文定稿）；导演台输出的是 **生成计划 `plan`**，不是一条视频。可选 LLM 按段把中文收成 H3 英文并写回 plan，再交给下游真正采样、最后拼接成片。详见 §6.5～§6.7。

## 5. 架构分层

```text
┌──────────────────────────────────────────────────────────┐
│ 导演台：切段·素材·中文·路线·续/新 → plan（不采样）         │
├──────────────────────────────────────────────────────────┤
│ （可选）LLMModelLoader 句柄 → 台内认线润色写回 plan        │  同 @；不 Queue；自启 server
├──────────────────────────────────────────────────────────┤
│ 模型收集：FL/Ref/混合 + TE + 双 VAE + LatentUpscaler 权重名 │  只收集；二采对齐社区 Latent Upscaler
├──────────────────────────────────────────────────────────┤
│ 段执行台：读 plan+模型包；按段选模型与采样；节点内循环采样 │  全段 / 单段；覆盖 or 新版本
├──────────────────────────────────────────────────────────┤
│ 选片 / 对比 / 拼接 → 成片                                 │  学 Easy-Media 结果列表
├──────────────────────────────────────────────────────────┤
│ 素材层：Load* → N0 项目库 / 单段 ReferenceMedia            │
└──────────────────────────────────────────────────────────┘
```

多段主路径**不再**是「取一段 → 图上焊死一套官方条件+KSampler」。各段可能换底模，必须按段循环；吐给外置 KSampler 不便做全段/单段/版本策略，故**采样在执行台节点内**。

**第一期交付重心**：素材层 + HTML Lab（导演台 → 执行台示意）。  
N1 归一：**多段不做**；定稿在导演台。

## 6. 模式定义

### 6.1 生成模式与模型分流（已拍板方向）

H3 在 Comfy 里实质是 **两套底模路由**，导演台要让用户一眼知道「这段在玩哪一挂」：

| 底模族 | 模式 | 典型素材 |
|--------|------|----------|
| **Base 族**（同一类 FL2VA/文生权重） | `T2VA` / `I2VA` / `FL2VA` / `L2VA` | 无图；或仅首/尾/首尾帧 |
| **Ref 族**（Ref2VA 权重） | `Ref2VA` + **玩法意图** | 任意 `ref_image_*` / `ref_video_*` / `ref_audio_*` 等 |

另加 **`自动`**：只看**本段**已绑素材（轨道上的引用），规则与排版台一致：

1. 有任一 ref 类素材 → **Ref 族**  
2. 否则：首+尾 → FL2VA；仅首 → I2VA；仅尾 → L2VA；都无 → T2VA  

人可覆盖自动结果；素材不足时报错，不静默降级。

#### Ref 玩法（比「一个 Ref 下拉」更重要）

Ref 不是一种玩法，而是一族。目标：**兼容多种玩法，并让用户直观知道「现在这段打算怎么玩」**。  
UI **不强制**单一大下拉；推荐用 **意图卡片 / 标签多选**（可叠），写入 plan，并驱动 summary 方括号任务类型 + LLM system 侧重。

| 玩法意图（示例 ID） | 用户能看懂的说法 | 典型素材 / 备注 |
|--------------------|------------------|-----------------|
| `reference_generation` | 普通参考生 | 图/视频参考外观场景 |
| `lip_sync` / `audio_lock` | 对口型 | 干声窗 + 人脸；可与 T8 lock 旁路配合 |
| `character_replace` | 换人 / 换身份 | 人物图 + 可选底视频 |
| `video_editing` | 视频编辑 | 参考视频 |
| `video_continuation` | 视频续拍 | 与 continuity=continue 常一起出现 |
| `keyframe_completion` | 关键帧补全 | 首尾或关键图 |
| `audio_reuse` / `audio_reference` | 音频复用 / 音频参考 | 参考音轨 |

可与排版台已有 Task Types 对齐，并允许扩展；**一段可勾多个意图**（例如「换人 + 对口型」），界面用短标签展示当前玩法，避免用户只看到一个模糊的「Ref2VA」。

```text
段上模式区（示意）：
  [ 自动 | Base 族… | Ref 族 ]
       ↓ 若 Base：再显 T2VA/I2VA/FL2VA/L2VA（或由自动填）
       ↓ 若 Ref：再显玩法卡片（普通参考 / 对口型 / 换人 / …）
  当前：Ref · 对口型 + 普通参考生
```

下游：`mode` 决定接哪套官方条件节点 / 加载哪类权重；`ref_intents[]` 决定提示词合同与可选 lock。

### 6.2 编排相关选项（与生成模式分开）

与生成模式**分开**，避免一个下拉塞爆。下列均为**人可配选项**，不是互斥的「只能选一种编排」：

| 选项 | 含义 | 阶段 | 人控要求 |
|------|------|------|----------|
| `单段` | 一次生成一段 | 第一期 | 默认路径 |
| `镜间关系` | 每段：接上一段（续拍）或全新镜头 | 多段阶段 | **逐段可选**；对标 Easy-Media Shot / Context 一类思路 |
| `放大二采` | latent 放大后再采 | 第二期+ | **全局或按段开关；默认可关，人决定是否启用** |
| `口型 / MV 多段` | 干声切窗 + 可选 lock | 第三期+ | 自动切 + 人改切点；每段素材与文案可改 |

### 6.3 可选能力开关（已拍板）

下列能力**不是强制主路径**，由人灵活控制：

| 能力 | 默认建议 | 关闭时行为 |
|------|----------|------------|
| **LLM 写提示词** | 可用可不用 | 手写英文 / 排版台 / `ReciveAndEdit` 直接出最终 prompt，仍可 Normalize（可选）后进官方节点 |
| **放大二采** | 可用可不用 | 只跑一采；工作流不因未接二采而失败 |
| **多段自动草案** | 多段时建议先开 | 人可清空/重写切点与每段文案；也可从全手动切点起步 |

实现时：开关应是明确控件或接线有无（未接 LLM 节点 = 不用 LLM），**禁止**做成「不接就报错 / 静默强制跑 LLM」。

### 6.4 多段 / 长视频：人机共驾（已拍板）

长视频、多镜头、音乐 MV 等**必须让人参与**，不能做成完全自动黑盒。

#### 心智

```text
自动草案 → 人审核与调整 → 再生成（可逐段 / 选段）→ 不满意只重跑该段
```

#### 自动可以做什么（初稿）

- 在**导演台内**：从素材包选出一路音频 → 点「自动切分」→ 时间轴标切点（类 T8 Planner，但是台内按钮，**不单独建草案节点**）
- 试听该音频：播放头竖条前进；可拖回、吸附切点、左右微调
- 每段中文草稿（可选规则模板）；镜间关系默认建议

#### 人必须能改什么

| 对象 | 说明 |
|------|------|
| **切点** | 自动往往不准（已知 T8 易切偏）；人在波形或秒数列表上增删拖拽切点 |
| **每段素材** | 每段可指定不同图 / 音 / 视频（仍来自原生 Load → 素材包引用，非节点内上传） |
| **每段要生成的内容** | 自动出一版后，人改导演字段或整段 prompt；可再可选调用 LLM 润色 |
| **镜间关系** | 逐段选择：**接着上一个镜头走（续拍 / Context）**，或 **整段全新镜头（Shot / 切断上下文）**；灵活可控 |
| **是否二采 / 是否用 LLM** | 见 §6.3，与多段正交 |

#### 生成节奏（产品要求）

- 主路径应支持：**审完再跑**，或 **审完一段生成一段**，而不是「plan 一旦提交就不可打断地跑完全曲」。
- 单段不满意：改该段素材 / 文案 / 切点后**只重跑该段**（后续是否作废视续拍依赖而定，需在实现时写清）。

#### 与外部包的对照（偷师不绑死）

| 点 | 参考 | 本需求差异 |
|----|------|------------|
| 自动切 + 分段文案 | T8 Vocal Lock | 切点与文案必须可回改；每段可不同素材；不绑单图 / 整链一键 |
| 接上镜 vs 新镜头 | Easy-Media Shot / Context | 逐段人可选；不强制用其 Project 清单 |
| 选段重跑 | Director / Easy 一类 | 纳入多段阶段验收 |

### 6.5 导演台：计划中枢与提示词归属（已拍板）

导演台（目标节点 N3 / HTML Lab 多段页）是**设置生成计划**的地方，不是直接吐出一条成片的地方。

**负责：**

- 接入素材清单（来自原生 Load → 素材包；台上只引用，不上传）
- 读取音频、自动/手动切分、分镜 / 段列表
- **按段**写用户意图（主路径用**中文**描述）、选该段生成路线（T2VA / I2VA / … / Ref2VA）、素材引用、continuity、二采等
- 输出整份 **`H3_SEGMENT_PLAN`（生成规则集合）** 给下游

**不负责：** 真正 H3 采样；节点内上传图。

**提示词写在哪：** 多段场景下，**每段需要的提示词就在导演台该段里写**（先中文，可选再转英文）。  
Brief / 排版台 / 图上 `LLMGenerator` 变为：

- **单段**简易路径仍可用；或  
- 导演台内的**助写工具**（高级字段编辑、单段润色），结果**写回 plan 该段**，不再与导演台并列成第二套「主写作入口」。

对标心智：Easy-Media「Editor 出 TRACKS_INFO → Project 才生成」；AIMixer Director「时间线里改每段 prompt → plan → 生成」。我们要同构，但素材走原生 Load，LLM 走**本地**（见 §6.7）。

### 6.6 按段 LLM 与两层「组合」（已拍板）

导演台输出的是**一堆段规则**，连续长片 = 多段多次生成，**不是**一条超长 prompt 喂一次 H3。

#### 中文 → H3 英文（可选）

```text
段上：用户选路线 mode + 中文想法 + 本段素材清单 + continuity
        ↓
按 mode 取内置 system（只含该 Task 规则；复用 prompts/h3/official/）
        ↓
（可选）LLM → 英文合规稿 → 写回该段 prompt_final
```

| 点 | 约定 |
|----|------|
| 要不要多次调 LLM | **要。** 启用时默认**一段一次**（按该段 mode 换 system）。UI「全部未定稿段一键转换」= 内部循环多次调用，对用户像一次操作。 |
| 一次塞全片所有段 | **不推荐**主路径（易串段、system 难对齐）。 |
| 段间连贯 | 可选在第 N 段 user 里带「上一段英文摘要」；仍是一次调一段。 |
| 内置 system | 按路线切换即可，不算麻烦；与现有 `H3PromptBuilder` 同一套文件，避免两套文案。 |

User 消息建议固定带：`【任务模式】` `【时长】` `【参考素材】` `【镜间 continue/new】` `【用户中文】`。

自动切段草案：优先填**中文草稿**（或极简占位）→ 人改中文 → 再点 LLM → 英文定稿。生成前该段应已有可用英文（手写或 LLM）。

#### 「组合」分两层（勿混）

| 层 | 含义 | 结果 |
|----|------|------|
| **文案组合** | 各段 LLM/手写结果写回 `plan.segments[i].prompt_*` | 仍是多条 prompt，**不**粘成一条 |
| **视频组合** | 各段官方采样得到 seg0/seg1/… → 选片 / 按序拼接（+ 可选混原曲） | 成片；与 LLM 无关 |

时间线：

```text
① 导演台编辑 plan（切点、素材、中文、路线、续/新）
② （可选）对每段 LLM → 英文写回 plan     ← 多次调用 / 批量循环
③ 人审 plan
④ 按段真正生成                           ← 多次 H3；continuity 决定是否带上段上下文
⑤ 拼接 / 选版本
```

### 6.7 本地 LLM 后端：复用 `LLMModelLoader` 句柄 + 台内自启 server（已拍板）

**需求：** 不用云端 API；用本地 Qwen 等写/优化英文提示词。  
**不要：**  
- 只填 `llama_server_url` 让用户手起 server；  
- 在导演台上再做一套「扫盘选 GGUF/mmproj」重复控件（本仓已有加载器）。

**结论：**

1. **配置唯一来源** = 已有 **`LLMModelLoader`**（只出 `H3_MODEL_HANDLE` 配置，不占显存）。  
2. **导演台增加输入口**接该句柄（与 `LLMGenerator` 同类型）。  
3. **点「本段→英文」时**：按句柄里的基座 / mmproj / ctx 等，由 **CZ 自启 llama-server** 跑润色，**不必 Queue 整张工作流**。  
4. **前端如何知道选了什么**：与 `H3PromptBox` 的 `@` **同一原理**——不执行也能沿连线读上游节点 **widget 当前值**。  
5. **提示词内容（已拍板）**：LLM **不是**自由闲聊。每次调用必须：
   - **system** = 仓库**内置** H3 规则，按该段**任务类型 / mode** 选取（与 `H3PromptBuilder` 同一套 `prompts/h3/official/`：core + 对应 Task 段；禁止导演台另维护一套冲突文案）。  
   - **user** = 结构化拼装：任务模式、时长、本段参考素材清单、镜间 continue/new、**用户中文描述**（及 Ref 玩法意图等）。  
   - **输出** = 符合该 Task H3 写作规则的英文 `prompt_final`，写回 plan 该段。

```text
[LLMModelLoader] ──H3_MODEL_HANDLE──► [导演台 N3]
     widgets: 基座GGUF / mmproj / 处理器 / ctx…
                    │
                    │  前端：认线 walkUpstream（同 prompt box @）
                    │  读出 loader.widgets → 等价句柄字段
                    ▼
              点「本段→英文」
                    │
                    ├─ system ← 内置 prompts/h3/official/（按本段 mode；Ref → Ref2VA Task）
                    ├─ user   ← 【任务】【时长】【素材】【continuity】【意图】【中文】
                    ▼
         CZ HTTP 路由：ensure llama-server(model, mmproj, …)
                    → /v1/chat/completions
                    → 英文合规稿写回 plan.prompt_final（仍不 Queue H3）
```

| 能力 | `@` 提示词框（已有） | 导演台 LLM（目标） |
|------|----------------------|-------------------|
| 要不要 Queue | **不要** | **不要**（润色本身） |
| 前端读什么 | 上游素材包 / Load 的接线与 widget | 上游 **`LLMModelLoader` 的 widget** |
| 后端干什么 | 无（仅插入 token） | 按读到的配置 **起/复用 llama-server**，并用**内置 system+中文 user** chat |
| 真采样 | — | 仍走 N8，与润色分开 |

**与 `H3PromptBuilder`：** 导演台润色应**复用**其「按 version+mode 拼 system / 拼 user」逻辑（抽共享函数即可），避免 Brief 与导演台两套文案。Ref 多选意图写入 user（或 summary），不另起无关 system 文件。详见 §6.6。

**与 `LLMGenerator`：**

| | `LLMGenerator`（单段图） | 导演台润色 |
|--|-------------------------|------------|
| 输入 | 同一 `H3_MODEL_HANDLE` | **同一句柄口** |
| system / user | 常接 Brief / PromptBuilder | **台内按段 mode + 中文**组同一套内置规则 |
| 加载方式 | 进程内 `llama-cpp-python`（Queue 时） | **子进程 llama-server**（台内按钮） |
| 配置 | 不重复造加载器 | **不重复**：共用 Loader |

学 T8「自启 server」；**模型选择落在已有 Loader**；**规则文案落在 `prompts/h3/official/`**。实现上 CZ 自写薄启动层（§10.2），不深绑 T8。

未接线柄或上游不是 Loader → 润色按钮报错提示接 `LLMModelLoader`。换模型 = 改 Loader 下拉，导演台下次润色读新值（必要时重启 server）。缺 mode / 缺中文 → 报错，不空跑。

HTML Lab：N3 画 **`llm_handle` 输入口**；侧栏示意「认到 Loader」+「本段将用 mode 对应内置 system」；**去掉**台内选模 / URL 控件。

## 7. 素材契约（强制）

### 7.1 正确路径

```text
Load Image / Load Video / Load Audio（官方或原生）
    → 素材库（可多于单次 H3 上限）→ 导演台按段挑选
    → 每段采样前：本段映射成官方口（≤9 图 / ≤3 视频 / ≤3 音频）
    → MiniMaxH3* 对应输入
```

单段、且不用导演台时：仍可用现有 `H3ReferenceMedia`（9/3/3）直接解包进官方。

### 7.2 关键：官方上限是「单次生成」，不是「整条多段项目」

现有 `H3ReferenceMedia` 按官方 Ref2VA 卡死：

- 参考图 ≤ **9**
- 参考视频（+ 可选伴音）≤ **3**
- 独立音频 ≤ **3**

多段时很容易不够用，例如：

- 段0 用图 1–9  
- 段1 要用图 2–10（滑动窗口）→ 项目里至少要 **10** 张图进库，但**每一次** Ref2VA 调用仍最多塞 **9** 张。

**拍板做法：两层分离**

| 层 | 名称 | 容量 | 作用 |
|----|------|------|------|
| **A. 项目素材库** | `H3MediaLibrary` → `H3_MEDIA_LIBRARY` | **可大于 9/3/3**（稳定 id：`lib_img_0`…） | 导演台轨道从库里挑；整条 MV 共用一个大库 |
| **B. 本段绑定 + 映射** | 段上 `media_refs[]` → 采样前 remap | **每段仍 ≤ 官方上限** | 把库 id 映射成该次调用的 `<Picture 1>`…`<Picture 9>` 与 `ref_image_0`… |

```text
库:  [img0][img1]…[img15][aud0][aud1]…     ← 可很多
段0: 绑 img0–img8  → 映射 Picture 1–9  → 一次 Ref2VA
段1: 绑 img1–img9  → 映射 Picture 1–9  → 另一次 Ref2VA
```

提示词里的 `<Picture N>` **以本段映射后的编号为准**（段与段之间同号可能对应不同库图）。台上 `@` / LLM user 只看本段有效清单。

若某段选了超过 9 张图：界面禁止提交或标红，**绝不能**静默截断导致错绑。

#### 项目素材库节点 UX（已拍板，学 Easy count + CZ 现有槽位形态）

**口增减 UX** 对标 Easy `MediaBridge`（改 count → 前端增删口）；**口类型与配对** 对齐本仓库已有 `H3ReferenceMedia`，**不要**做成整段 `VIDEO` 一口。

控件仍是三个整数：`image_count` / `video_count` / `audio_count`。

| count | 长出什么口 | 类型 | 说明 |
|-------|------------|------|------|
| `image_count = N` | `image_1…N` | **IMAGE** | 静图参考 |
| `video_count = V` | `video_1…V` | **IMAGE**（帧序列） | 视频的**画面**；与官方/本仓一致，用 IMAGE batch，不是 VIDEO 口 |
| 同上 | `video_audio_1…V` | **AUDIO** | 与上面**一一对应**的视频伴音；可空（无声视频） |
| `audio_count = A` | `audio_1…A` | **AUDIO** | **独立**音频（干声 / BGM 等），与视频伴音分开 |

**例子：** `video_count=2`、`audio_count=2`、`image_count=0` 时，节点上应出现：

```text
video_1        (IMAGE)   ← 视频1画面
video_audio_1  (AUDIO)   ← 视频1伴音
video_2        (IMAGE)   ← 视频2画面
video_audio_2  (AUDIO)   ← 视频2伴音
audio_1        (AUDIO)   ← 独立音频1
audio_2        (AUDIO)   ← 独立音频2
```

共 **2 个 IMAGE + 4 个 AUDIO**。一个「视频素材」= 画面口 + 伴音口 两半，不是单个 VIDEO 输入。

上游接线：

- 画面：`Load Video`（或拆帧）→ `video_i`（IMAGE）  
- 视频伴音：同片音轨 → `video_audio_i`（AUDIO）  
- 独立音：`Load Audio` → `audio_j`

库上限建议首版 **27 图 / 9 视频对 / 9 独立音频**（官方单次仍是 9/3/3；视频对里伴音不占「独立音频」名额）。Python 声明 optional 到库上限；执行只读 `1…count` 已接线槽。

与现有路径分工：

| 节点 | 上限 | 用途 |
|------|------|------|
| `H3ReferenceMedia`（现有 Autogrow） | 官方单次 9 图 / 3 视频对 / 3 独立音 | **单段** → Unpack → 官方 |
| **`H3MediaLibrary`（新建）** | 库上限（同上槽位形态，count→口） | **多段项目库** → 导演台 |
| 本段 pack / Unpack | ≤9/3/3 | 每次采样前从库裁出 |

> Easy MediaBridge 用 `video_*` 接 `*`/`VIDEO` 整包；**我们不照搬该口类型**，只偷师 count 驱动增减。槽位语义跟本仓 `ref_image_` / `ref_video_`（IMAGE）+ `ref_video_audio_` + `ref_audio_` 一致。  
> 也不做 Easy「一根 IMAGE 口虚拟多线合并」。

单段、且不用导演台时：仍用现有 `H3ReferenceMedia`（9/3/3）直接解包进官方。

推荐长期：**库节点与「官方一次调用包」职责分开**，和「每段可不同图」一致。

### 7.3 禁止

- 在 CZ 导演 / 提示词 / 生成节点内做「上传图片」控件。
- Easy / Director 式「节点内媒体库上传后才能选」作为主路径。
- 把整条多段项目的全部图一次性塞进同一次官方 Ref2VA（超过上限或错绑）。

### 7.4 与提示词引用

- 库内用稳定 id；**写出官方 prompt / 接官方口之前**再变成紧凑 `<Picture N>`。  
- 编号与**该次**解包口 1:1；跨段不要假设 Picture 1 永远是同一张库图。

## 8. 提示词主链（改造重点）

> **多段：** 写作与润色主战场在导演台（§6.5～§6.7）。本节描述**单段**图上链路，以及归一等可复用零件；勿再把「Brief→LLM→排版台」理解成与导演台平行的第二套多段产品。

### 8.1 现状问题

| 现有节点 | 现状角色 | 问题 |
|----------|----------|------|
| `H3PromptBuilder`（H3 参数包装） | 组 system / user 给 LLM | 不管出口是否合规官方字段 |
| `H3PromptFormatter`（排版台） | 手工结构化拼装，**不接 LLM** | 与 Builder 成两条产品线 |
| `H3PromptBox` | `@` 插入引用 | 夹在中间，主路径不清 |
| `LLMGenerator` | 本地推理（进程内） | 出口缺少强制归一；导演台即时润色不适合强依赖 Queue |
| `ReciveAndEdit` | 手改文本 | 可保留为改稿位 |

用户体感：不知道主用哪条；LLM 结果结构不稳；排版台很重却不帮生成。

### 8.2 目标主链

**多段（主推心智）：**

```text
导演台按段：mode + 中文 + 素材引用
  →（可选）本机 LLM HTTP，按 mode 换 system → 英文写回 plan
  →（可选）Normalize
  → 下游按段采样 → 拼接
```

**单段路径 A — 选用 LLM（图上节点）：**

```text
中文想法 + 生成模式 + 时长/分辨率 + 素材清单（来自 bundle）
        ↓
① H3PromptBrief（改造自 H3PromptBuilder）
        → system_prompt, user_message, mode_hint,（透传）media_bundle
        ↓
② LLMGenerator（已有；或日后指向同一 llama-server）
        → raw_english / 多模态看图（若接 mmproj）
        ↓
③ H3PromptNormalize（新建，或改造排版台后端）
        → 按 mode 校验/补齐官方字段结构
        → 输出最终 prompt + 可选 H3_PROMPT_PACK
        ↓
④ 可选 ReciveAndEdit / 排版台「载入结果手改」
        ↓
⑤ 官方条件节点
```

**单段路径 B — 不用 LLM（同等合法）：**

```text
手写英文 / H3PromptBox / 排版台直接出稿
        →（可选）Normalize
        →（可选）ReciveAndEdit
        → 官方条件节点
```

### 8.3 职责切分

| 环节 | 负责 | 不负责 |
|------|------|--------|
| Brief | 模式、时长、分辨率、素材文字清单、系统提示词版本（单段图上） | 最终字段拼装对错；**不强制用户必须接 LLM**；**多段不取代导演台写作** |
| LLM | （可选）按规则写英文草稿；导演台侧优先本机 HTTP | 采样、落盘；**未接线/未点按钮时整链仍可用** |
| Normalize | 结构合规、缺字段提示、与 pack 同步 | 替用户创作剧情 |
| 导演台 | 多段：中文/英文定稿、mode、素材引用写在段上 | 真正采样 |
| 排版台 / 手改 | 单段主写作，或导演台某段的高级字段编辑 | 强制绑定采样 |
### 8.4 与排版台文档的关系

- `H3_PROMPT_PACK` 字段结构继续以 `docs/H3-提示词排版台-需求说明.md` 为准。
- 统一工作流要求：无论是否经过 LLM，归一结果应能填进同一 pack，避免两套 schema。
- 排版台在「不用 LLM」时是合法主写作入口之一；在「用 LLM」时是二次修改 / 看结构入口。

### 10.1 包清单

| 包 | 态度 | 可用点 | 不用点 |
|----|------|--------|--------|
| **官方 Comfy H3** | 必须 | 条件、采样、模型加载 | — |

| **Easy-Media** | 参考不绑定 | 版本选片；Shot / Context；**台内 HTTP 写提示词的交互**（我们改接本机）；`continuity_mode` / MotionContext 流水线 | 云 API 依赖、Project Combine 清单、节点内上传、多轨作为底座 |

| **AIMixer Director** | 参考交互 | 多 task_type、选段重跑思路 | 巨石节点、自建上传 |
| **TimelineDirector** | 参考交互 | 参考时间线 UX；**自研段间 motion context**（可开关） | GPL 纠缠的核心编排照搬需谨慎评估 |

原则：**偷师交互与数据形态，不继承对方产品边界与私有落盘格式。**

### 10.2 第三方依赖策略（已拍板）

目标：吃对方的**能力**，不吃对方的**产品壳**；对方修 bug / 提速时尽量免费受益，接口变更时只坏一处适配器。

| 对方提供什么 | 策略 | 说明 |
|--------------|------|------|
| **官方 Comfy / 本仓已有节点** | **直接复用** | 图上连线，或进程内调同一套公开 `FUNCTION` |
| **稳定算法能力**（如 Latent Upscaler） | **软依赖 + 适配器** | 探测安装 → 调公开节点入口 → 自有窄接口；不深 import 私有函数 |
| **产品壳 / UX / 时间轴 / 选片墙** | **自己写** | 只学交互；不 import 对方节点类；避免 GPL / 巨石绑定 |
| **接口乱、巨石、强 UI 绑定** | **只借思路 + CZ 薄层** | 不合约则旁路或自写，不焊进主路径 |

**禁止：**

- 深 import 对方包内私有 helper / 改文件结构即炸的路径。
- 把对方整包源码默认 vendoring 进 CZ（除非对方大破且必须钉死行为，且带归因与对齐 commit 说明）。
- 业务节点（N8 等）里散落第三方 import；一律进 `adapters/`（或同等单文件）薄层。

**软依赖调用约定（以 Latent Upscaler 为例）：**

1. 启动或首次用时探测：`NODE_CLASS_MAPPINGS` / 动态 import；未安装则能力不可用。
2. 只调对方节点类的**公开 `FUNCTION`**（与用户在图上拖该节点等价）。
3. CZ 自暴露窄接口，例如 `upscale_latent(samples, model_name, scale) -> samples`；N7 只收权重名，N8 只调适配器。
4. README / 依赖说明写清：**可选依赖 + 已测版本范围**（不必做成 pip 硬依赖）。
5. **探测失败或接口对不上 → 硬失败、清晰报错**（如「请安装/升级 Comfyui_Minimax_h3_latent_Upscaler」）；开了 refine 却调不通时禁止静默跳过二采。

**对方更新的利弊怎么接：**

- 修 bug / 提速：用户更新对方包即可，CZ 多数时候零改。
- 改公开接口：只改适配器 + 更新「已测版本」说明；必要时钉建议版本。
- 行为必须钉死且上游大改：再考虑最小 vendoring（最后手段）。

**口诀：** 看得到的节点 `FUNCTION` 可以调；私有 helper 不要摸；对方面板与产品叙事不要绑；接口变了改适配器，不改整条业务链。

| **P5 多段 / 口型** | 可编辑 plan（切点、每段素材、每段文案、镜间关系）+ 选段重跑 | 自动草案 + 人改后再生；每段可不同 ref；接上镜/新镜头可选；不绑 Vocal Lock 整链 |
| **P6 选片** | 简单版本目录 + 预览合并 | 不依赖 Easy Combine 清单 |

每阶段结束应更新本目录「变更记录」或单独修改记录文件。

## 13. 风险与取舍

1. **一口吃成巨石**：若把采样循环、多段 UI、选片全塞进单节点，必难维护 → 坚持分层与分阶段。
2. **硬接外部清单**：Easy / T8 落盘格式不同，强焊会反复破 → 编排层自建简单契约。
3. **LLM 不稳定**：选用 LLM 时无 Normalize 则「符合规则」难保证 → 校验；**也可用不用 LLM 规避**。导演台侧优先 **llama-server** 减轻与 H3 同进程卡死（见 LLM 备忘）。
4. **模式与素材不一致**：静默降级会出废片 → 宁可报错。
5. **口型与花式参考冲突**：多段换景会漂脸；属产品取舍，文档里写清，不假装 T8 同稳。
6. **全自动长片**：切点与文案不准时废片率高 → 以人机共驾为主路径，自动仅草案。
7. **一次 LLM 写完全片**：易串段 → 坚持按段调用；文案组合进 plan，视频组合在采样后。

## 14. 待拍板事项（实现前确认）

### 14.1 已拍板（需求补充）

1. **长视频 / 多镜头**：必须人机共驾；自动草案 + 人审可改（切点、每段素材、每段内容、镜间续/新）。
2. **放大二采**：人可启用或关闭，不强制。
3. **LLM**：人可用或不用，不强制；不用时手写 / 排版台 / 手改仍完整可用。
4. **P1 优先**：仍默认 **单段五模式骨架先**；多段人机共驾在 P5 / Lab 做透。
5. **多段提示词归属导演台**；导演台输出 **plan（生成规则）**，不是成片。
6. **按段 LLM**（一段一次 / 批量=循环）；文案写回 plan，视频事后拼接。
7. **按段 mode 切换内置 system**（复用 `prompts/h3/official/`；与 Brief 同一套；user = 中文+任务元数据 → 英文 `prompt_final`）。
8. **导演台本地润色**：输入口接 **`LLMModelLoader` → `H3_MODEL_HANDLE`**；前端不 Queue 即可认线读 Loader 控件（原理同提示词框 `@`）；背后 CZ 按该配置自启 llama-server；**调用内容按 §6.6/§6.7 第 5 点**。导演台**不再**自带模型/mmproj/URL 控件。
9. **自动切分**：导演台内按钮（选 bundle 音频 → 切分标注 → 试听播放头 / 微调）；**不单独建计划草案节点**。
10. **模式**：Base 族与 Ref 族分流（对应两套 H3 模型）；支持自动按本段素材判断；Ref 用玩法意图（卡片/标签，可多选）表达对口型/换人/普通参考等，不局限单一下拉。
11. **段素材**：图/视频轨选 bundle；中段可选上段尾帧/下段首帧；提示词里再用 `@` 写用法。
12. **素材库 vs 单次上限**：项目库（N0，学 Easy count→口）可大于官方 9/3/3；**每段绑定后 remap** 成该次调用的 Picture 1–9；禁止超限静默截断。单段仍用 `H3ReferenceMedia`。
13. **多段采样**：各段可能换底模 → **必须按段循环**；主路径用 **段执行台节点内采样**（全段循环 / 只跑当前段），不主推「吐 model/cond 给外置 KSampler」做多段。
14. **模型收集**：6 线口（FL / Ref / 混合 / TE / 双 VAE）+ 下拉选 **Latent Upscaler 权重**（`models/latent_upscale_models/`，与 `Comfyui_Minimax_h3_latent_Upscaler` 同目录同文件）。**不是**第四个扩散 MODEL。
15. **段执行台 ≈ 计划台**：同构只读轨道；不能改计划；每段设模型、sampler、sigma、seed、refine（倍数手填）+ **Motion-Context 开关**（默认关）。
16. **版本策略**：覆盖或另存新版本（学 Easy-Media）。
17. **成片**：独立 **N6** 结果列表对比选片 → 拼完整视频（与 N8 分离，Lab 已如此）。
18. **放大二采**：社区通行——低分一采 → Latent Upscaler（权重 + 倍数）→ 高分二采；**默认全关**；仅 N8 按段开；**放大倍数手填**（约 1.0–4.0，非下拉）；计划台不设 refine；未选权重却开 refine 则报错。
19. **第三方依赖**：算法包软依赖调公开 `FUNCTION` + 适配器；UX/壳自写；禁止深 import 与默认 vendoring。见 §10.2。
20. **节点边界**：N8=段执行台（采样）；N6=选片对比/拼接；Lab 已如此，不再另议合并。
21. **Queue 行为**：看执行台用户怎么选——「生成全部」则循环各段；「只生成当前段」则只采该段；覆盖 / 另存新版本同理。
22. **Motion-Context**：与二采一样，**用户开关**（默认关）；开则可用重叠帧等参数。Easy=`shot`/`context`、TimelineDirector=段间引导；T8 提示词包不做采样续拍。实现软依赖社区包或自写薄层（§10.2），不焊死必须安装。
23. **导演台音频轨**：**要真波形**（解码音频画波形），不要假条糊弄。
24. **段素材绑定**：靠轨道 + **`@` 列表**即可；**不做**素材缩略图墙。
25. **H3 多字段结构**：用户只写中文意图；**不**在 UI 暴露官方六段等字段；由 LLM + 内置 system 自动写成合规英文。
26. **单段**：统一流的特例（段数=1），走同一套导演台/执行台/选片；不另做「单段 Normalize」产品路径。
27. **llama-server 运行时**：**参考 T8** 自启方式；模型配置仍来自 `LLMModelLoader`。
28. **mmproj AUTO**：后做或不做；第一期手动在 Loader 选。
29. **开发自测**：见 **§16**——Lab/样式/逻辑尽量开发侧先测（含截图）；真采样与重启仍需用户环境；默认「先自测再请用户 Queue」。

## 16. 开发自测约定（已拍板）

目标：减少「改完就甩给用户：重启 Comfy → 重新加节点 → 肉眼找 bug」的循环；**尤其前端样式**（下拉字色看不见、宽度重叠截断等）应尽量由开发侧先截图验过。

### 16.1 开发侧应自己做

| 类型 | 做法 |
|------|------|
| **HTML Lab / 纯前端** | 浏览器打开 Lab → 截图检查配色、对比度、溢出、截断；修完再交付 |
| **Python 逻辑 / 适配器** | 脚本或单测直接调，不依赖 Queue 出片 |
| **Comfy 已在跑且只改 `web/js`** | 优先刷新网页验证；用浏览器截图看节点面板 / 下拉 / 自定义编辑器 |
| **样式类问题** | 主动截图 + 读 CSS/DOM；专门盯字色、固定宽度、重叠 |

交付真节点时写清：

- 是否必须 **重启 ComfyUI**（改了 Python / 注册表则通常要）  
- 是否 **只刷新网页** 即可（多数纯前端扩展）  
- 建议点哪几个控件看样式 / 行为  

流程默认：**先自测（截图 / 脚本）→ 再请用户点 Queue 或看真采样**。用户不是唯一质检员。

### 16.2 仍需要用户环境配合

1. **改节点 Python / `NODE_CLASS_MAPPINGS`** → 多半要重启 Comfy（可代写重启命令，进程在用户机上）。  
2. **真采样 / 显存 / 模型加载** → 依赖本机权重与 GPU，不适合每次全量代跑。  
3. **节点 I/O 变更后的旧图** → 可能要重建接线。  
4. **视觉 100% 无回归** → 无现成 Comfy widget 回归套件；截图人工看会漏边缘情况。

### 16.3 落地习惯

1. 样式与交互先在 **Lab / 可截图路径** 过一遍，再嵌真 Comfy 节点。  
2. 能脚本测的后端契约用脚本测，少为逻辑 bug 逼用户重启。  
3. 用户保持 Comfy 开着且允许用浏览器时，**下拉看不见字、宽度叠字**等应由开发侧先截图修一轮。
